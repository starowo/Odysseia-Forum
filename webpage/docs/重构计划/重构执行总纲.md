# Odysseia 前端 V2 重构执行总纲

## 1. 文档目的

这篇文档只负责三件事：

- 给 V2 重构设边界
- 给现有专题文档分工
- 给实施阶段定顺序

它不是长篇白皮书，也不重复各专题细节。

---

## 2. V2 要解决的核心问题

当前前端最大的问题不是功能不够，而是结构失衡。

### 现状问题

1. 页面过重
   - [`SearchPage`](../../src/pages/SearchPage/index.tsx:40) 体量过大，承担了布局、筛选、请求、分页、banner、预览、引导等多种职责

2. 状态边界不清
   - 搜索条件、分页、预览、banner 等混在 [`useSearchStore`](../../src/features/search/store/searchStore.ts:65)
   - 其中一部分本应属于 URL 状态或服务端状态

3. 布局职责重复
   - [`MainLayout`](../../src/components/layout/MainLayout.tsx:14) 有布局职责
   - [`SearchPage`](../../src/pages/SearchPage/index.tsx:453) 又复制了一套侧边栏和主内容结构

4. 浮层体系分散
   - 搜索建议、通知中心、帖子预览、浮动 banner、看板娘都在不同层级挂载
   - 缺少统一的 overlay 规则和 z 轴规范

5. 重构文档分类还不够清楚
   - 架构、布局、状态、体验、测试、安全有交叉
   - 状态管理应该单独成类，不应继续散落在其他文档里

## 3. V2 重构范围

### 本轮纳入

- 应用骨架与布局体系
- 搜索链路与 URL 状态
- 状态管理分层
- 设置持久化规范
- 浮层体系
- 安全基线
- 测试基建
- 文档体系重组

### 本轮不强制纳入

- 真正的推荐算法上线
- 全新视觉品牌重做
- 后端搜索协议重写
- 大规模商业化功能
- 所有页面一次性重做

---

## 4. V2 硬规则

1. 搜索条件以 URL 为准，不再以 store 为准
2. React Query 只管理服务端状态
3. Zustand 只保留客户端 UI 状态
4. 页面组件只负责编排，不承载过重数据逻辑
5. 所有浮层进入统一 overlay 体系
6. 所有持久化设置必须做 schema 校验和默认值回退
7. 所有富文本渲染必须经过安全白名单
8. 所有关键页面必须具备加载、空、错、成功四态
9. 所有新依赖都要说明引入收益
10. 每个阶段都必须有验收标准

## 7. 阶段验收标准

### 架构验收

- 页面组件不再承担过重业务逻辑
- 搜索主链路不再依赖单一巨型 store
- 布局职责不再在多个页面重复实现

### 状态验收

- 搜索条件刷新后不丢失
- 浏览器前进后退可恢复筛选状态
- 服务端结果不写入 Zustand

### 布局验收

- 主滚动域唯一
- 浮层不被父容器裁剪
- 移动端无明显滚动穿透

### 安全验收

- 无裸 `dangerouslySetInnerHTML`
- 外链行为统一
- 持久化状态有校验回退

### 测试验收

- 核心工具库有自动化测试
- 关键链路至少有基础集成测试
