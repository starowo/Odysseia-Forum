# Odysseia 前端体验细节打磨

## 1. 这篇文档的新定位

这篇文档不再负责：

- 状态管理讨论
- 架构设计讨论
- 测试策略讨论

这篇文档现在只负责：

- 体验规范
- 交互优先级
- 哪些细节值得做，哪些先放后面

---

## 2. 优先级分层

## P0：V2 首轮必须做

这些属于重构完成度的一部分，不是可选装饰。

### 搜索体验基础项

- 搜索输入和结果状态一致
- URL 和页面状态一致
- 有统一的空状态、错误状态、加载状态
- 搜索历史和建议不造成状态混乱

### 列表体验基础项

- 网格和列表切换行为一致
- 骨架屏统一
- 图片失败有回退
- 关键交互有即时反馈

### 移动端基础项

- 主要操作不被输入法遮挡
- 弹层打开时不滚动穿透
- 顶栏、侧栏、底部导航逻辑明确

### 反馈基础项

- toast 风格统一
- 成功、失败、空状态文案统一
- 看板娘只做增强，不接管核心可用性

---

## P1：V2 稳定后建议补齐

这些能提升体验，但不应该挡住主重构。

- 更强的搜索零输入态
- 更丰富的搜索联想内容
- 卡片 hover 快捷操作
- 多图快速扫视
- 更强的通知体验细节
- 更细的动效统一

---

## P2：愿景项

这些更像产品升级，不应和基础重构绑死。

- 首页推荐流
- 趋势标签云
- 命令面板
- 更强的个性化分发
- 更重的视觉焕新

---

## 3. 搜索体验规范

### 规则一

输入状态、URL 状态、结果状态必须一致。

### 规则二

搜索无结果时，不只显示冷冰冰的空白块。

### 规则三

搜索报错时，必须给出可重试动作。

### 规则四

高级筛选不应把搜索逻辑继续做复杂，而应帮助用户理解当前筛选条件。

---

## 4. 列表与卡片规范

### 必做项

- 列表和网格切换规则清楚
- 卡片加载中有骨架屏
- 图片失败有占位
- 点击卡片和点击快捷操作不冲突

### 建议项

- PC 端 hover 反馈轻一点，不做炫技
- 卡片信息层级稳定，标题、作者、标签不要频繁跳动

---

## 5. 四态规范

所有关键页面至少定义四态：

- 加载中
- 空状态
- 错误态
- 正常态

重点页面：

- 搜索页
- 关注页
- 通知面板
- 预览面板

这部分必须统一，不要每个页面各写各的。

---

## 6. 移动端规范

### 必做项

- 弹层优先考虑底部抽屉而不是居中 modal
- 输入相关面板避免被键盘顶坏
- 底部导航如果存在，职责必须稳定

### 不要做的事

- 继续把桌面侧边栏思路强塞到移动端
- 为了视觉好看牺牲点击和滚动体验

---

## 7. 看板娘和情感化边界

这是项目特色，但不能反过来绑架基础体验。

### 原则

1. 看板娘负责增强，不负责补漏洞
2. 错误提示首先要可读，再考虑情感化
3. 空状态插图不能替代有效操作引导

### 可做

- 空状态插图
- 成功反馈联动
- 节制的轻量动画

### 不建议优先做

- 把大量核心流程都绑到看板娘状态机上
- 让业务组件直接控制看板娘细节

---

## 8. 动效规范

### 原则

- 动效服务于理解，不服务于炫耀
- 优先轻量、短时、稳定
- 支持 reduced motion

### 当前建议

- 基础 hover 和 focus 用 CSS
- 复杂进出场再用 Framer Motion
- 不要给列表页堆过多进入动画

---

## 9. 验收标准

这篇文档对应的验收只有一个方向：

**体验统一，而不是体验花哨。**

满足以下条件即可：

1. 关键页面四态一致
2. 搜索体验不混乱
3. 移动端基础交互可用
4. 看板娘和动效不过度干扰主流程
5. P0 和 P1 边界清楚

2. 核心搜索体验 (The Search Experience)

搜索面板不仅是输入框，更应该是一个智能的“导航枢纽”。

2.1 模糊联想与富文本预览 (Rich Typeahead Autocomplete)

分栏展示：当用户输入拼音或部分字母时，下拉面板不只是出文字，而是分区域展示匹配结果：

🎯 标签 (Tags)：高亮匹配的字符，右侧显示该标签下的帖子数量。

👤 作者 (Authors)：直接展示作者的圆形头像 + 昵称。用户点击头像直接搜该作者的所有资源。

📄 最近浏览/热门帖子：展示帖子的小缩略图和截断的标题。

拼音/模糊匹配支持：即使用户输入的是小写拼音（如 mota），也能联想到对应的中文标签（如 魔塔）。

2.2 搜索历史与“零输入”状态 (Zero-State Search)

用户刚点击搜索框（还未输入任何字）时：

展示“最近搜索”历史（支持一键清除）。

展示“猜你想搜”（根据用户偏好推荐的 Tag）。


6. 全局动效系统与库选型 (Global Motion System)

现代应用的流畅感来源于克制且恰到好处的动画。我们将采取 "三级动效架构"：

6.1 库选型策略

基础状态层 (Tailwind CSS)：所有简单的 Hover（悬停）、Focus（聚焦）、Active（点击）效果，一律使用 Tailwind 的 transition-all duration-200 ease-in-out 实现，避免引入第三方库造成的性能损耗。

核心逻辑层 (Framer Motion 主力)：作为 React 领域最强的动效库，全面接管组件卸载/挂载 (Mounting)、布局变动 (Layout Shifts) 和 手势操作 (Gestures)。

重型视觉层 (GSAP 备选)：仅针对极其复杂的首页滚动时差序列 (ScrollTrigger) 或 SVG 路径动画时按需懒加载，常规业务避免使用。

6.2 核心应用场景 (Framer Motion)

共享布局过渡 (Shared Layout Transitions)：当用户点击一张小卡片时，使用 layoutId 属性让封面的图片平滑地“飞”到详情页的大图位置，实现类似 iOS 相册点开图片的无缝体验。

优雅卸载 (AnimatePresence)：当卡片在搜索过滤中被移除，或者弹窗关闭时，提供平滑的淡出 (fade-out) 或缩放消失 (scale-down) 效果，而不是生硬地闪烁消失。

弹簧物理效果 (Spring Physics)：对于下拉刷新、底部抽屉 (Bottom Sheet) 拖拽等交互，弃用死板的 CSS 缓动 (ease)，全面采用物理弹簧属性 (Spring)，增加手感的“Q弹”与真实感。

6.3 无障碍动效原则 (Motion Accessibility)

强制引入安全网：在所有 Framer Motion 配置和 Tailwind 属性中，支持 prefers-reduced-motion 媒体查询。当操作系统开启“减弱动态效果”时，将所有飞入/飞出动画降级为最基础的 50ms 淡入淡出 (Fade)，杜绝引起用户眩晕。


长列表渲染 (List Rendering)

原生 DOM 渲染，海量卡片卡顿

react-virtuoso / @tanstack/react-virtual

虚拟滚动，只渲染可视区域内的卡片节点，极致优化内存和滚动帧率。


3. UI 基础与设计系统 (Design System) 重构规划

针对 V1 中“硬编码”泛滥的问题，V2 将全面引入 设计令牌 (Design Tokens)，通过 CSS 变量和 Tailwind 的扩展机制打好基底。

3.1 抽象化设计令牌 (Design Tokens)

除了现有的主题色 (Theme Colors)，必须在全局 globals.css 中抽象出以下变量，使其成为可配置项：

圆角系统 (--radius)

放弃硬编码的 rounded-md, rounded-lg。

定义基础变量 --radius: 0.5rem;。全局的卡片、按钮、输入框都基于此计算 (例如 calc(var(--radius) - 2px) )。

潜力： 可以在设置中增加 “UI 风格：直角 / 微圆角 / 圆润” 的选项。

排版系统 (--font-sans, --font-serif)

统一全局字体栈，定义标题、正文、辅助文本的严格规范。

潜力： 设置中增加 “阅读字体” 切换（如：系统默认、等宽字体、特定风格的衬线体）。

密度与间距 (Layout Density)

定义基础的网格 Gap 和 Padding 变量。

潜力： 设置中增加 “布局密度：紧凑 / 标准 / 宽松”。在海量资源展示时，“紧凑模式”是非常受核心用户欢迎的功能。

3.2 全局覆盖物与模态框系统 (Overlay System)

坚决摒弃各处散落的自定义 z-index。

统一使用 shadcn/ui 的 Dialog, Drawer, Toast, Tooltip。

确保所有模态框具备：背景模糊 (Backdrop blur)、按 Esc 键关闭、点击外部关闭、焦点锁定 (Focus trap) 等现代 Web 标准行为。

3.3 交互反馈与动画统一 (Interaction & Motion)

建立全局的动画过渡速度曲线变量 (e.g., --transition-fast, --transition-smooth)。

统一按钮的 Hover、Active、Disabled 态表现。

适配系统级无障碍规范：增加 focus-visible:ring 的键盘导航高亮，并在用户系统开启减少动画时（@media (prefers-reduced-motion)），禁用非必要的过渡动画。


4.2 资源卡片与性能优化

骨架屏 (Skeleton)： 使用一致的呼吸灯骨架屏替代丑陋的 Loading Spinner。

图片懒加载与降级： 封装一个 <LazyImage /> 组件，包含：

IntersectionObserver 懒加载。

加载过程中的低分辨率模糊占位 (Blurhash) 或骨架背景。

加载失败时的优雅回退 (Fallback icon)。

无限加载 (Infinite Scroll)： React Query 的 useInfiniteQuery 配合 IntersectionObserver，实现顺滑的瀑布流或网格流触底加载。
