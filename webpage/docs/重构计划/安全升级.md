# Odysseia 前端安全升级

## 1. 目标

这篇文档只关心前端安全基线。

重点不是追求完美安全，而是先把当前最现实的风险收住：

- Markdown 渲染
- 外部链接
- token 存储
- 本地持久化状态
- 第三方资源加载

---

## 2. 当前风险面

这个项目的风险主要来自两类内容：

1. 外部用户生成内容
   - 帖子内容
   - Markdown
   - 外部链接
   - 图片地址

2. 本地客户端状态
   - token
   - 设置持久化
   - 被污染的 localStorage

---

## 3. Markdown 安全规则

项目里已经有 [`MarkdownText`](../../src/components/common/MarkdownText.tsx:1) 这类入口，V2 要明确规则。

### 硬规则

1. 不直接渲染未经处理的 HTML
2. 禁止裸 `dangerouslySetInnerHTML`
3. Markdown 渲染必须走受控组件
4. 外链必须统一处理

### 当前建议

- 继续优先使用 `react-markdown`
- 明确允许的 Markdown 能力范围
- 如果必须支持 HTML，必须增加白名单清洗

---

## 4. 外链安全规则

这个站天然会出现大量外部链接。

### 必做项

1. 所有外链统一加安全属性
   - `target="_blank"` 时必须同时带 `rel="noopener noreferrer"`

2. 区分可信域和非可信域
   - Discord
   - GitHub
   - 自家域名
   - 其他未知站点

3. 对未知域名支持跳转前提醒

### 不要继续分散处理

不能让每个组件自己决定外链行为，必须统一在链接渲染层处理。

---

## 5. Token 与认证安全

当前请求 token 由 [`apiClient`](../../src/lib/api/client.ts:12) 从 localStorage 读取。

### 现实问题

- localStorage 中的 token 一旦遇到 XSS，风险最高
- 当前方案能跑，但安全上不够理想

### V2 处理原则

#### 短期方案

- 继续沿用当前 token 方式
- 先把 XSS 和外链风险压低
- 统一 token 清理和过期处理

#### 中期方案

- 评估迁移到 HttpOnly Cookie
- 这需要后端一起配合，不属于前端单独可完成项

### 额外要求

- token 提取入口统一
- [`App`](../../src/app/App.tsx:34) 和 [`ProtectedRoute`](../../src/components/ProtectedRoute.tsx:6) 不应继续重复处理 token hash

---

## 6. 本地持久化状态安全

当前设置主要在 [`lib/settings.ts`](../../src/lib/settings.ts:3) 中处理。

### 风险

- localStorage 数据可能被手改
- 旧版本数据可能结构不完整
- 污染数据可能导致页面异常

### V2 规则

1. 所有持久化设置恢复前必须做 schema 校验
2. 校验失败必须回退默认值
3. 建议加入版本号和迁移逻辑
4. 不信任本地缓存内容

---

## 7. 图片与第三方资源加载

资源站类项目很容易忽略图片链路风险。

### 风险点

- 外部图片暴露 referer
- 失效图片导致大量坏图
- 第三方域资源不可控

### V2 规则

1. 图片加载策略统一
2. 需要评估 `referrerPolicy`
3. 不在前端随意做高风险跨域图片处理
4. 图片失败必须有回退策略

重点组件包括：

- [`LazyImage`](../../src/components/common/LazyImage.tsx:1)
- [`fetchImagesApi`](../../src/features/threads/api/fetchImagesApi.ts:23)

---

## 8. 依赖与供应链要求

前端安全不只是代码问题，也包括依赖。

### 规则

1. 只引入必要依赖
2. 对 Markdown、HTML、图片处理、浮层库保持谨慎
3. 定期做依赖审计
4. 锁定版本，不随意漂移

---

## 9. 部署侧建议

这部分不要求当前马上全部实现，但文档要留目标。

### 建议关注

- CSP 策略
- 图片域白名单
- connect-src 白名单
- script-src 约束

如果后续走 Cloudflare 或其他静态托管，这部分应该补进部署文档。

---

## 10. 验收标准

满足以下条件，才算前端安全基线达标：

1. Markdown 渲染链路无裸 HTML 注入
2. 所有外链行为统一
3. token 处理入口统一
4. 设置恢复对脏数据有容错
5. 图片失败与第三方资源加载有基本防护策略
